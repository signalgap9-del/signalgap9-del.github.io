The problem

Running autonomous coding agents on a real repo fails in a specific way: gray failures. The session reports success while a queue silently stalls, a deploy goes green without running its migration, or an edit touches a file it shouldn't. Diff review can't catch these — the damage is in what the agent didn't do. The fix isn't a better prompt; it's machinery around the agent.

Architecture

LayerComponentWhat it does
Lifecyclesession-start.mjsSession opens informed: dirty tree, stale locks, open obligations, incident index
PreToolUseagent-guard.mjs · file-guard.mjsDeterministic regex guards block dangerous shell commands and writes to secret/migration/runtime files — sub-50ms, zero model calls
PostToolUseagent-ledger.mjsEvery tool call appended to action-log.jsonl (secrets redacted) — the session is auditable as a trace
UserPromptSubmitprompt-guard.mjsExternal-knowledge questions get a mandatory source-verification instruction injected
Stopclaim-guard.mjsFiles changed but no test ran → loud "unverified" advisory instead of silent green
Reviewgate.mjs → dep-audit.mjs → jev-gate.mjsDeterministic secret/suppression scan → npm supply-chain audit → typed LLM judgment (14 constraints) with persistent state
Orchestrationops/dispatch/Dispatch contract + rules for delegating work to autonomous sessions
Knowledge.devin/skills/ · docs/ · templates/11 domain skills, ~30 pattern docs, AGENTS/ADR/incident templates

Design principles

  • Deterministic before stochastic — anything that can be a regex is a regex; model calls are reserved for genuine judgment
  • Fail closed — blocked actions produce errors the agent must route around legitimately
  • State that accumulates — persistent gate state means resolved findings never re-block; the system learns this repo over time
