Why it exists

Every new backend or AI service needs the same unglamorous day-one baseline before touching real traffic: supply-chain pinned CI, secret scanning, static security analysis, user-journey smoke E2E, auditable artifact promotion, and architecture decision records. Teams either skip half of it under deadline pressure or copy brittle unhardened YAML from blog posts.

production-starter packages those controls into a single, opinionated GitHub template assembled strictly from official upstream standards (GitHub Security, OpenSSF, SLSA, Playwright, and UK Government GDS / Ministry of Justice operating handbooks).

What is inside

  • Supply-chain hardened CI workflows: every third-party GitHub Action is pinned to a full 40-char commit SHA from a vetted release (≥7-day Dependabot cooldown), running with persist-credentials: false, least-privilege job permissions:, and explicit timeouts.
  • Security & provenance gates: CodeQL static analysis (JS/TS + GitHub Actions workflows), OpenSSF Scorecard SARIF grading, dependency vulnerability review blocking high-severity introductions on PRs, TruffleHog diff secret scanning, and actions/attest-build-provenance (SLSA) signing build artifacts promoted once across staging → production.
  • Stranger-journey E2E + autonomous agent guardrails: Playwright smoke config that verifies a real signed-out user render (not just a 200 health ping), paired with .devin/config.json and AGENTS.md rules denying destructive git/deploy commands without human approval.
  • Operational & architectural memory: Nygard ADR templates (docs/adr/), AI-native spec-first intent/ templates, release-please Conventional Commit automation, and curated runbook references based on UK GOV.UK (The GDS Way) and Ministry of Justice platform alerting standards.
