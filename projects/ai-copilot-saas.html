The product

An independent AI startup in production (stealth): a real-time copilot that watches your screen and talks back — live multimodal sessions where a model sees rolling video of what you're doing while an agent session owns the tools and maintains persistent cognitive state. I designed, built, and operate it solo across product, backend, edge infrastructure, billing, and operations.

Split-agent architecture

The core design decision: separate perception from agency.

  • Perception — a video model ingests rolling screen windows (~5s A/V segments, rolling 4) and produces what the user is doing, live.
  • Agency — an agent session owns the tool layer: a 12-tool MCP server, an OpenAPI 3.1 surface, and a skill catalog injected per call (including auto-routed sales modes).
  • The two run as separate sessions so each can be reasoned about, retried, and priced independently — a failure in tool dispatch never corrupts what the model saw.

Edge runtime, multi-tenant by default

  • Cloudflare Workers + Durable Objects — session state lives in DOs, giving each live session a single-threaded, strongly-consistent home without standing up a stateful cluster.
  • Per-user knowledge stores — every user's RAG corpus is a siloed store mapped server-side (user_id → store); retrieval is always called with tenant scope enforced in the request builder, never trusted from the client. An unscoped knowledge attach is treated as a cross-tenant leak, not a bug.
  • D1 + KV + R2 for relational state, session caches, and media — the whole product runs on the edge with no always-on server to babysit.

The unglamorous parts that matter

  • Billing correctness — multi-provider payments (PayPal, NOWPayments crypto, x402 USDC agent wallets) behind signature-verified webhooks, idempotency keys on every credit mutation, an atomic integer micro-USD credit ledger, a 15-minute reconciliation sweep, and per-session spend caps so one runaway loop can't burn a user's balance.
  • Usage metering → observability — provider pricing vendored from LiteLLM's published rate table (the cost_calculator pattern) stages a usage_event row per call into OpenMeter + BigQuery: cost, latency, and token spend per user per session — which is what made the $12→$8/session optimization measurable instead of vibes.
  • Deploy safety — a 12-step predeploy gate (diff scan for forbidden patterns, prod-truth checks on D1 tables and Durable Object migration monotonicity, typecheck, real wrangler dev boot of the built worker, route smoke, visual and copy audits) that must pass before anything reaches production — the same gate runs as a required PR check.
  • Tests as contract — npm test (32 tests) + npm run check gates provider API contracts against real calls; assumptions about Gemini/OpenAI behavior are verified, not trusted.

Honest limitations

Solo-operated: there is no on-call rotation because there is no team. Provider concentration is real — the product is only as available as its model APIs. The per-user knowledge-store silo design has a documented Phase-2 path (pooled store + server-side metadata filters) for when user count outgrows per-user stores. These are written down in the repo's design docs, not hidden.
